# Abstract 

Language agents can adapt from experience in interactive environments, but current reflection-based methods can only self-correct within a single task instance. Whether such experience can be distilled into reusable lessons that improve performance on future unseen tasks remains unclear. We address this problem by introducing the In-context Training (ICT) task, a framework for evaluating cross-task self-improvement in language agents. In ICT, a reflector model observes trajectories collected by an actor model and generates system prompts intended to improve the actor’s performance on future unseen tasks. We then propose an RL-based training pipeline for learning such reflections directly from experience, without human-provided examples. Across ALFWorld and MiniHack, our trained reflectors outperform an untrained baseline on most held-out task families, showing that the ability to learn from experience can itself be learned. In some cases, we observe generalisation beyond the benchmark on which the reflector was trained, to substantially different environments. Finally, we introduce MetaGym, a generic Python library for constructing meta-environments, enabling future research on self-improving language agents. 

# 1 Introduction 

In recent years, there has been a growing interest in using large language models (LLMs) as decision-making agents in interactive environments [ 18 , 17 ]. In this setting, LLMs act as agents that leverage their language capabilities to interact with external environments, producing tokens that are interpreted as actions [ 21 ]. When faced with an unfamiliar environment, a general-purpose agent should be able to learn and adapt its behaviour from experience in order to find an optimal policy for action [ 16 , 11 , 23 , 14 ]. Humans handle this task with ease. For example, when playing chess for the first time, a person may begin with an initial strategy in mind and, after each game, reflect on their experience to refine that strategy for future matches. In LLM-based agents, the agent’s policy is determined not only by the model’s parameters, but also by the prompt provided to the model, which specifies how the agent should act in the environment [ 21 , 3]. Learning and adapting may therefore be achieved by modifying the prompt provided to the model, making prompt optimisation a natural mechanism for self-learning in language agents. This approach has three main advantages: (1) it avoids the compute-heavy pipeline of fine-tuning LLMs for each spe-cific task through gradient descent; (2) it leverages the linguistic abilities of the model to support rapid learning from only a small number of experiences; and (3) it offers a degree of transparency, since the accumulated experience is represented solely in natural language and can be directly inspected. Recent studies have explored self-improvement in language agents through autonomous prompt modification, using self-reflection mechanisms [ 14 , 22 , 5– 7]. In this setting, an LLM generates a reflection following an unsuccessful attempt at an interactive task. The reflection considers both the agent’s actions and the resulting feedback from the environment, and is then used to guide the agent’s next attempt by providing hints and suggesting how to avoid similar mistakes. However, existing work primarily focuses on self-correction by repeatedly attempting the same task until success. This introduces several important limitations. First, the agent acquires experience only within a single task instance, and the resulting knowledge is not transferred across tasks. Once a task has been solved, the agent must repeat the full reflection process from scratch when encountering a new task. This is inherently inefficient, since insights from one task could often generalise to similar tasks (e.g., “in maze-solving tasks, avoid revisiting the same path” ). Under the current paradigm, however, the agent is forced to relearn such lessons for each task. Second, in many real-world settings, repeating the exact same task is not possible. For example, in a game of chess one cannot require an opponent to reproduce the same sequence of moves, and in a cooking scenario a mistake may irreversibly consume the available ingredients. Although the ability to learn online from experience across tasks is highly desirable, it remains unclear whether self-reflection mechanisms can produce reflections that generalise well enough to improve performance on previously unseen tasks. We therefore ask the following research question: Can LLMs be trained to generate self-reflections that facilitate cross-task self-improvement, and if so, how? .To address this, we first define the In-context Training (ICT) task, a framework for evaluating the ability of LLMs to learn from experience for cross-task self-improvement (see Figure 1). The ICT task implements a simple self-learning loop through a dual-LLM design. The first model is the actor , which serves as the operational agent interacting with external environments according to a system prompt. Crucially, at each turn of the ICT task, the actor faces a new unseen batch of tasks and has only one chance to solve each task. The second model is the reflector , which evaluates the actor’s performance and proposes an improved system prompt for the the next turn. The goal of the reflector is to learn from the actor’s collected experiences in order to generate a system prompt that generalises across tasks within a given family of tasks. For example, in a maze-solving task, the reflector should learn from previously encountered mazes in order to produce a system prompt that enables the actor to solve any unseen maze drawn from the same task family in a single attempt. Next, we demonstrate that the ability to learn from experience is itself a learnable skill by introducing a fine-tuning pipeline to train an LLM to generate reflections that facilitate cross-task self-improvement. We train a reflector to analyse a given system prompt alongside experiences collected under that prompt, and to generate an improved system prompt for future unseen tasks. Our method does not rely on human-provided examples. 2We evaluate our approach on ALFWorld [ 15 ] and MiniHack [ 9], two benchmarks comprising diverse interactive environments. Using these benchmarks within the ICT framework, we show that a reflector trained on a set of task types can generalise and improve performance on previously unseen task types using only a small number of gathered experiences. We also show that, in some cases, the model generalises beyond the benchmark on which it was trained, transferring to substantially different environments. Finally, we introduce MetaGym, a generic Python library for constructing gym-like meta-environments from any gym-like environment [ 2]. We release MetaGym as a tool to support future research on self-improvement in LLM agents within the ICT framework and beyond (https://github.com/yuvalshalev1/MetaGym ). Our contributions can be summarised as follows: 1. A training pipeline for learning reflection strategies for cross-task self-improvement without reliance on human-provided labels. 2. The In-context Training task, a framework for evaluating online self-improvement of LLMs that generalises across task instances. 3. MetaGym , a Python library for constructing meta-environments from Gym-like environments. 

# 2 Related Work 

Prompt Optimisation. Previous studies have demonstrated the potential of LLMs for prompt optimisation in static tasks [ 20 , 4 , 1 ]. Yang et al. [20] optimise prompts for mathematical reasoning and question answering using closed-source LLMs, and Choi et al. [4] propose a bi-level framework that jointly optimises task-specific user prompts and a cross-task system prompt. In both cases, the optimiser observes only final outputs or aggregate accuracy, not how its prompts shaped the model’s behaviour during problem solving. In our setting, however, the optimiser observes full interaction trajectories, enabling us to study its ability to learn from the agent’s behaviour. Agrawal et al. [1] leverage full reasoning trajectories to optimise prompts through iterative updates to a prompt pool. However, their scoring procedure relies on evaluating multiple candidate prompts on the same batch of task instances. In contrast, our setting assumes that each task is encountered only once and learning must occur online from non-repeatable experience. More broadly, these works optimise prompts using external procedure rather than fine-tuning the optimiser itself, leaving open whether LLMs can be trained to learn better optimisation strategies. 

Prompt Optimisation for LLM-Agents. Recent work has explored prompt optimisation for LLM agents in interactive environments, while transferring experience across tasks [ 10 , 24 ]. Sarukkai et al. [10] maintain an external database of self-generated successful trajectories and retrieve similar exam-ples as in-context demonstrations for the actor. This method relies on embedding raw past trajectories directly into the prompt, rather than consolidating them into a structured representation. However, prior work shows that in-context demonstrations are not always effective, even when produced by hu-man experts [ 8]. Zhao et al. [24] similarly rely on an external mechanism, extracting “insights” from pairs of past experiences and maintaining them through a voting procedure, before combining them with selected raw experiences to construct task-specific prompts during inference time. These methods therefore transfer experience through external memory and retrieval, but leave open the question of whether an LLM can be trained to learn reusable reflective strategies for cross-task self-improvement. 

Reflection for Self-Correction. Shinn et al. [14] introduce reflection for LLM agents as a feedback loop in which an agent analyses its behaviour after failing a task and uses this analysis to guide subse-quent attempts. Since then, several works have explored how to train LLMs to reflect more effectively in interactive environments. Yao et al. [22] , Ge et al. [6] and Feng et al. [5] use dual-LLM architecture that separates actor and reflector, with the former training only the reflector and the latter training both components jointly using a gradient policy. Most recently, Jiang et al. [7] proposed a meta-RL framework in which a single LLM acts as both actor and reflector. However, all of these methods focus on self-correction through repeated attempts at the same task. # 3 The In-context Training Task 

Here, we introduce the In-context Training (ICT) task, a framework for evaluating whether large language models can learn from experience to achieve cross-task self-improvement. ICT is designed to capture a realistic setting in which the same task cannot be repeated, and the only opportunity for improvement lies in future tasks. The framework is intentionally minimalistic, aiming to measure the model’s intrinsic learning ability rather than optimise performance through external machinery. The motivation is to capture a diverse set of system prompts arising from different stages of the ICT process, which correspond to varying degrees of required improvement. For example, if the reflector receives a system prompt that succeeds on one task in the batch but fails on the others, it should be able to analyse the factors that contributed to the successful case and generalise them to the remaining tasks. Conversely, if the reflector receives a system prompt that succeeds on all tasks in the batch, it should generate a new system prompt that remains highly similar to the previous one, potentially reproducing it exactly. 

Reward Signal. As described in Equation (2), the reflector generates a system prompt sp i conditioned on the previous system prompt sp i−1 and the last batch of trajectories obs i−1 collected by LLM act un-der sp i−1. Its immediate task is therefore to analyse how the previous system prompt led to the actor’s observed performance on the previous batch e(i−1) , and to improve the prompt in light of the issues re-vealed by those trajectories. # 5 Experiments 

5.1 Experimental Setup 

All our experiments were conducted using the Qwen2.5-7B-Instruct model [ 19 ] and the verl frame-work [ 13 ] for RL-based fine-tuning. The datasets were constructed as described in Section 4, using 

r = 128 ICT loops of N = 4 turns each, with Qwen2.5-7B-Instruct serving as both the actor model and the base reflector model. For each benchmark, we trained two reflectors: one with batch size 

k = 3 and another with batch size k = 5 . The reflection prompts used in our experiment are detailed in Appendix A. Training hyperparameters and compute resources are reported in Appendix B. 

MetaGym. Task execution for both the ICT loop and the fine-tuning procedure is managed by MetaGym, our library for meta-environment construction for LLM-agentic tasks. MetaGym instan-tiates an interactive meta-environment in which each meta-action is represented by a system prompt, 5Figure 2: A single training step illustrated on an ALFWorld-Cool and Place example. A system prompt and its associated episode batch are sampled from the dataset and fed into the reflector, which gen-erates multiple candidate system prompts. Each candidate is scored by replaying the same tasks with the frozen actor, and the resulting scores drive advantage estimation and parameter updates via GRPO. and each returned meta-observation is a batch of rollouts generated by an actor. Internally, it spawns task instances and executes them in parallel. See Appendix C for more details and a usage example. 

Task Partitioning. The objective of the proposed training approach is to train a reflector that performs effectively on the ICT task, where the goal is to generate a general system prompt that achieves strong performance across tasks within a given task type. A straightforward evaluation strategy would be to divide task instances into training and validation sets. However, this is insufficient: a reflector trained on one task type could simply memorise a high-performing prompt for that type and reproduce it at test time, thereby bypassing the in-context reasoning the model is intended to learn. To mitigate this, we partition tasks by type rather than by instance, yielding disjoint meta-train and meta-test 

sets, each comprising distinct task types. Each task type consists of a collection of similar tasks, from which the reflector is expected to extract transferable insights that generalise to other tasks within the same type. During training, the reflector is exposed exclusively to task types from the meta-train set. At evaluation time, it is required to generalise to previously unseen task types in the meta-test set, generating reflections based solely on in-context observations available at inference time. 

5.1.1 Environments 

To construct the meta-train and meta-test sets, we use agentic benchmark environments that could be partitioned into distinct task types. Specifically, we use ALFWorld [ 15 ] and a subset of MiniHack [ 9]. For each benchmark, we train a dedicated reflector on the tasks in the corresponding meta-train set, and then evaluate it on tasks drawn from the meta-test set of the same benchmark. 

ALFWorld. ALFWorld is a benchmark comprising six task types, all set in a partially observable, house-like textual environment. Following Jiang et al. [7] , we use Pick and Place , Examine in Light ,

Clean and Place , and Heat and Place as the meta-train set, and Cool and Place and Pick Two and Place as the meta-test set. For dataset creation, we execute the ICT loop 32 times for each of the four meta-train task types. Further details are provided in Appendix D. 

MiniHack. MiniHack is a benchmark comprising many tasks in two-dimensional grid world environ-ments. To construct a meta-set with different task types, we use a collection of eight 5x5 grid world environments. We use MiniHack-Room-Random-5x5-v0 , MiniHack-Eat-v0 , MiniHack-Wield-v0 , and 

MiniHack-Wear-v0 as the meta-train set, and MiniHack-PutOn-v0 , MiniHack-Zap-v0 , MiniHack-Read-v0 , and MiniHack-Room-Dark-5x5-v0 as the meta-test set. For dataset creation, we execute the ICT loop 32 times for each of the four meta-train task types. Further details are provided in Appendix E.

LLMs Can Be Trained to Achieve Cross-Task Self-Improvement. Table 1 reveals that across nearly all evaluated tasks and environments, our trained reflector consistently outperforms the untrained Qwen2.5-7B-Instruct baseline, demonstrating that the ability to learn from experience is itself a learnable capability. Reflectors trained on one set of task types successfully transfer their improved reflection ability to unseen tasks types – providing direct evidence that learning from experience is itself a learnable meta-skill. The one exception is the Zap task in MiniHack for the k=3 condition, which is the hardest task and may require larger batches to meaningfully learn from. Notably, our results indicate that untrained Qwen2.5-7B-Instruct was also able to improve the initial system prompt when conditioned on sampled episodes of the actor, suggesting that the ability to extract reusable lessons from experience already exists in the model to some extent. 

More Meta-Turns Lead to Better Performance. Figure 4 presents the average best win rate achieved up to each turn, aggregated across all tasks for each experimental group. Performance improves consistently with additional meta-turns across all four groups and, crucially, continues to increase beyond turn 4, the boundary of our training data. This is an important finding: during training, our model was exposed to prompts created only by the first 4 turns of the ICT loop, yet at test time, it was able to recursively improve its own generated prompts further beyond this horizon. In the ALFWorld experiments, 55% ( k=3 ) and 45% ( k=5 ) of the best-performing prompts were achieved after turn 4, while in the MiniHack experiments, 32.5% ( k=3 ) and 37.5% ( k=5 ) emerged after turn 4. Notably, 25% of the best ALFWorld k=3 prompts were not attained until turn 10, suggesting that further meta-turns may yield additional improvements. 

Effect of Batch Size. The batch size plays two important roles that can influence the performance of the reflector. First, it determines the number of episodes observed by the reflector in each turn, thereby affecting the diversity of experiences from which it can learn. Notably, when a task is difficult, a small batch size may contain no successful episodes, making it more challenging for the reflector to extract useful lessons in the absence of positive examples. Second, batch size affects the fine-tuning process of the reflector itself: during training, if none of the generated candidate prompts is successful on any of the replayed tasks, the GRPO algorithm cannot compute advantages because all rewards are zero. A larger batch size increases the likelihood of obtaining a positive reward signal, particularly when tasks are difficult and rewards are sparse. Results are shown in Table 2, alongside the initial prompt and Qwen2.5-7B-Instruct baselines. The reflector trained on MiniHack with a batch size of k=5 outperforms the untrained Qwen2.5-7B-Instruct baseline on 4 out of 6 tasks, while achieving comparable performance on the remaining two. Notably, on both the Examine in the Light and Heat and Place tasks, it outperforms Qwen2.5-7B-Instruct even under the k=3 condition, which we previously observed in Table 1 to be easier within ALFWorld. This is a significant finding, as it demonstrates transferability between fundamentally different benchmarks. By contrast, the k=3 reflector does not achieve improved performance and, in some cases, performs worse than the untrained model. We attribute this, as discussed earlier, to more difficult training at smaller batch sizes, where the reward signal is sparser. 

5.3 Limitations 

In our experiments, we trained only the reflector model in order to isolate the contribution of prompt evolution to actor performance. However, maintaining separate actor and reflector models is computationally expensive in practice, as it requires holding two models in memory simultaneously. Training a single model to serve both roles could yield further performance gains. During the ICT loop, we used a fixed held-out task set to identify the best-performing prompt at the end of each loop. In real-world settings, such a repeatable evaluation set may not be available, necessitating alternative mechanisms for determining when to stop adaptation. One such alternative is lifelong learn-ing – continuously updating the system prompt without a fixed stopping criterion – though this raises open questions about the long-term stability of the generated prompts, which we leave for future work. 

# 6 Conclusion 

In this work, we investigated whether LLMs can learn from their own experience in-context in the realistic setting of online learning. We introduced the In-context Training (ICT) task as an framework for evaluating cross-task self-improvement, in which an LLMs repeatedly analyses batches of unseen episodes and generates system prompts intended to improve performance across a task family. To train models for this setting, we proposed an RL-based fine-tuning approach that derives reward signals from replayed input tasks. Across held-out task types, our trained reflectors consistently outperform an untrained baseline, showing that leaning from experience is itself a learnable capability. We believe this has important implications for language agents. Our work provides both an evaluation framework and a training methodology for cross-task self-learning, a capability likely to matter for general-purpose agents operating in open-ended environments. We hope it shifts attention from reflection within a single task instance to reflection across tasks. Because our approach requires no annotated examples and applies directly to agentic benchmarks, it is readily extensible. # C MetaGym 

MetaGym is a Python library designed to support prompt optimisation and self-improvement research for LLM agents. It natively implements the ICT task from the perspective of the reflector as a meta-agent. Each meta-action is a system prompt, and each returned meta-observation is a batch of rollouts generated by the actor conditioned on that prompt. Internally, the meta-environment spawns a batch of task instances and executes them in parallel using a chosen actor, providing native infrastructure for running the ICT loop described in section 3. MetaGym wraps a Gym-compatible environment [ 2] inside a Gym-like meta-environment and handles the parallel execution and trajectory collection required by the ICT framework. In our experiments, all task execution across ALFWorld and MiniHack was managed through MetaGym. The library ships with built-in support for both benchmarks and provides instructions for integrating new environments, with the aim of supporting future research on prompt optimisation and self-improvement in LLM agents. # E MiniHack Details 

MiniHack environments are procedurally generated, so task instances are produced by sampling random seeds. The reflector receives task batches sampled from a designated range of training seeds, while a fixed set of 32 seeds is held out and used consistently as the validation set for the ICT loop. Each episode is limited to 25 steps, with the exception of the k=5 training run, where this limit was reduced to 18 steps to keep episode trajectories within the model’s context length. 15 MiniHack natively exposes a large number of actions, many of which are irrelevant to the tasks in our benchmark. To reduce ambiguity and keep the context concise, we always provide the actor with a curated list of available actions that are suitable for our task set, rather than the full action space.
