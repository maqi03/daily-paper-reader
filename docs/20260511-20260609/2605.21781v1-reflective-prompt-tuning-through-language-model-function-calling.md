## 摘要
大语言模型（LLMs）在指令遵循和复杂推理方面日益增强，使得提示成为无需参数更新即可调整模型的灵活接口。然而，提示设计仍然耗费人力且对格式、措辞和指令顺序高度敏感，这促使了自动提示优化方法的发展，以减少人工工作并保持推理时的灵活性。然而，现有方法通常搜索候选提示或使用由单个样本或小批次驱动的固定评估-改进流程，限制了它们捕捉系统性错误模式并基于失败历史进行针对性编辑的能力。我们提出了反思性提示调优（RPT），一个利用LLM函数调用来模拟人类提示工程师迭代工作流程的框架。LLM优化器调用诊断函数，该函数在整个优化集上评估目标模型，总结反复出现的失败模式，并返回结构化的诊断报告。优化器使用该报告以及之前报告的累积记忆来为下一次迭代修改提示。RPT还通过在诊断反馈和最终提示选择中使用校准信号来支持置信度感知优化。在三个推理任务中，RPT将初始提示的性能提升了最多12.9个百分点，与现有最佳方法保持竞争力，并改善了置信度校准。我们的分析表明，RPT在多跳推理和数学推理任务上尤其有效，能够产生与诊断出的失败模式相符的针对性提示修改，从而提升任务性能和校准效果。

## Abstract
Large language models (LLMs) have become increasingly capable of following instructions and complex reasoning, making prompting a flexible interface for adapting models without parameter updates. Yet prompt design remains labor-intensive and highly sensitive to formatting, phrasing, and instruction order, motivating automated prompt optimization methods that reduce manual effort while preserving inference-time flexibility. However, existing methods often search over prompt candidates or use fixed critique-refine pipelines driven by individual examples or small batches, limiting their ability to capture systematic error patterns and make targeted edits grounded in failure history. We propose Reflective Prompt Tuning (RPT), a framework that uses LLM function calling to simulate the iterative workflow of human prompt engineers. An LLM optimizer calls a diagnostic function that evaluates the target model over an entire optimization set, summarizes recurring failure modes, and returns a structured diagnostic report. The optimizer uses this report, together with an accumulated memory of prior reports, to revise the prompt for the next iteration. RPT further supports confidence-aware optimization by using calibration signals in diagnostic feedback and final prompt selection. Across three reasoning tasks, RPT improves over initial prompts by up to 12.9 points, remains competitive with state of the art, and improves confidence calibration. Our analyses show that RPT is especially effective on multi-hop and mathematical reasoning, producing targeted prompt revisions that align with diagnosed failure patterns and lead to gains in task performance and calibration.

## 1. 研究背景与核心问题

- **背景痛点**：大语言模型（LLM）在下游任务中高度依赖提示（prompt）设计，但手动编写提示极其耗时且对措辞、格式、指令顺序高度敏感，泛化性差。
- **现有方法局限**：当前自动提示优化方法（如 ACE、GEPA、MIPRO）大多使用固定评估‑改进流水线，依赖单个样本或小批量反馈，缺乏对系统性失败模式的诊断与历史记忆，难以做出有针对性的、基于全局错误模式的提示修订。
- **本文目标**：提出一种模拟人类提示工程师迭代工作流程的框架，利用 LLM 的函数调用能力进行“诊断‑反思‑修订”闭环，在提升任务性能的同时改善置信度校准。

## 2. 方法：Reflective Prompt Tuning (RPT)

RPT 将提示优化形式化为一个诊断驱动的迭代过程，核心组件包括：

- **诊断函数（Diagnostic Function）**
  - **行为收集与评分**：在当前提示 `pt` 下，对全量优化集 `D_train` 运行目标模型，记录推理轨迹、最终答案以及语言化置信度，计算任务指标和 Brier 分数。
  - **失败检测与评判**：识别错误实例，使用评判 LLM 对每个错误生成最多 3 条诊断（如推理错误、证据缺失、格式错误、过度自信等）。
  - **聚类反复失败模式**：采用 ClusterFusion 将单样本诊断聚合成主题族 `Ct = {(ak, dk, Sk)}`，提取系统级的失败模式。
  - **生成结构化报告**：输出包含当前提示、评估指标和筛选后的失败主题（仅保留占比 > 10% 的簇）的报告 `Rt`，并存入外部记忆 `M<t`。

- **反思性提示修订**
  - 优化器 LLM 接收当前报告 `Rt` 和历史记忆 `M<t`，推断提示的缺陷，产生下一次迭代的提示 `pt+1`。
  - 记忆机制帮助解决信用分配问题，使优化器能跟踪持续失败、回顾此前修改，避免重复无效编辑。

- **置信度感知优化**
  - 诊断报告中包含校准信号，提示选择时联合优化任务性能和 Brier 分数：
    ```
    p* = arg max Φ(O(pt; Ddev))
    ```
    其中 `Φ` 将任务得分与校准惩罚（如负 Brier 项）结合。

- **停止条件**：当开发集性能达到平台期或不再可能提升时输出 STOP。

## 6. 主要结论与发现

1. **性能提升**：RPT 在所有任务和优化器设置下均能稳定超过初始提示，最高在 HotPotQA 上提升 +12.9 分，在 LiveBench‑Math 上提升 +12.4 分，在 Formula 上提升 +11.7 分。
2. **与 SOTA 竞争力**：在多跳和数学推理任务上，RPT 经常达到或超越现有最佳方法（尤其在 GPT‑5 驱动时），仅 Formula 上 ACE 略胜一筹。
3. **优化器能力影响**：更强的优化器 LLM（如 GPT‑5 > GPT‑5‑mini）能显著提升 RPT 的整体表现。
4. **校准改进**：将校准信号纳入诊断反馈与提示选择，RPT 能够在提升任务性能的同时降低 Brier 分数，改善模型的自我评估可靠性。
5. **诊断驱动修订**：优化轨迹分析表明，RPT 产生的提示修订与诊断出的失败模式高度对齐，尤其在 HotPotQA 和 LiveBench‑Math 上，失败类型到补丁的映射具有针对性，且含验证步骤、答案格式约束等补丁通常带来性能提升。

## 7. 优点与亮点

- **新颖的框架设计**：将 LLM 函数调用与“全局诊断‑历史记忆‑结构化反馈”结合，模仿人类工程师的迭代反思过程。
- **系统性失败捕捉**：通过对全优化集进行聚集和聚类，有效识别反复出现的失败模式，而非仅依赖局部样例。
- **记忆与信用分配**：利用历史报告和修订记录，帮助优化器跟踪持久问题，避免重复修改，提高优化轨迹的质量。
- **置信度感知优化**：首次将校准作为第一类信号同时融入反馈回路和提示选择，实现任务性能与可靠性的联合提升。
- **可解释性分析**：通过聚类对齐和补丁效果分析，为优化过程提供了深入的诊断‑修订关联解读。

## 8. 不足与局限

- **任务覆盖有限**：仅测试了三类推理任务（多跳问答、数学推理、领域数值推理），未涉及开放式生成、代码、对话、工具使用等更广泛场景。
- **模型依赖性强**：
  - 目标模型固定为 GPT‑4.1，未在开源或小规模模型上验证。
  - 优化器依赖闭源前沿 LLM，若优化器能力不足，RPT 的性能优势会减弱。
- **计算开销大**：每轮迭代需在全量优化集上运行目标模型并进行批量评判与聚类，可能限制其在超大规模数据集或长轨迹优化中的可扩展性；作者建议未来可引入采样或检索等方式缓解。
- **不能解决所有错误**：对于深层数学推理、领域特定规范等根深蒂固的失败，仅靠提示修订可能无法根除，仍需结合工具、外部验证或微调。
- **置信度代理问题**：校准基于语言化置信度，而非真实不确定性估计，其可靠性可能受提示风格影响，需在实际高风险场景谨慎验证。
