Abstract 

Soft prompt tuning is a parameter-efficient method for adapting LLMs to specific tasks, but suffers from a lack of interpretability. Build-ing on recent work on interpreting soft prompts (Ramati et al., 2024), we explore how train-ing a dedicated soft prompt to natural language translation model can yield higher translation quality. In particular, in both quantitative and qualitative comparisons on multiple Datasets of Datasets (DoDs), we demonstrate that our trans-lator produces fluent, accurate verbalizations that outperforms existing training-free meth-ods like InSPEcT. In addition to advancing interpretability, our work suggests a promis-ing downstream application: soft prompts op-timized on small, open-source models can be translated into portable text prompts that, when deployed on larger closed-API models, exceed the performance of the original soft prompt and, in some cases, even few-shot learning. 

1 Introduction 

As an alternative to manual prompt engineering, LLM researchers and practitioners sometimes em-ploy soft prompt tuning , whereby a sequence of learnable embeddings is prepended to the input sequence and then fed to an LLM for fine-tuning on some downstream task. Soft prompt tuning matches, and in some cases, surpasses fine-tuning of LLMs while containing significantly fewer pa-rameters (Liu et al., 2022; Lester et al., 2021). Due to their ease of implementation and training, soft prompts are versatile and can be applied to a wide variety of tasks such as text classification (Buch-ner et al., 2024), relation extraction (Peng et al., 2024), and even drug discovery (Liu et al., 2026). Further, because soft prompts do not modify the model weights themselves, there is reduced risk of catastrophic forgetting (Vu et al., 2022).  

> *Equal contribution.

In contrast to LLM parameters or adapters, soft prompts share the same embedding space as natural language tokens, and it is thus tempting to hope that they might be more interpretable than other LLM fine-tuning methods. Unfortunately, naive projec-tions of soft prompts into discrete token space are often misleading and yield contradictory results (Khashabi et al., 2022). Some works have found that soft prompts occupy regions in the embedding space that are distinct from those containing natural language (Bailey et al., 2023). Methods designed to optimize soft prompts for interpretability often incur reduced task performance (Patel et al., 2025). Until recently, it was widely thought that soft prompts, while useful as a light-weight LLM op-timization method, were fundamentally not inter-pretable. However, the InSPEcT technique (Ramati et al., 2024) showed that the same LLM that uses soft prompts for prediction can also be utilized to elicit textual verbalizations of soft prompts. The technique is training-free: it simply relies on the model’s in-context learning ability to continue gen-erating tokens after being fed the soft prompt as input. Such verbalizations, it turns out, often pro-vide a glimpse into how the soft prompt operates. Nonetheless, InSPEcT leaves much to be desired in terms of reliable, clear descriptions of what the learned soft prompt means and what behaviors it induces in the LLM using it. In this paper, we explore whether there are stronger, more effective methods of interpreting soft prompts. In particular, instead of relying on in-context learning, we train a dedicated transla-tion model, using the same architecture (but differ-ent model weights) as the LLM on which the soft prompts were trained. We find that our approach is promising and outperforms InSPEcT.

2 Related Works 

A number of works have attempted to interpret soft prompts into natural language via obtaining their nearest discrete token projections. However, Khashabi et al. (2022) showed that these naive pro-jections of soft prompts into discrete token space are often misleading, completely uninformative, and in some cases contradictory to the underlying task through a phenomenon they termed prompt waywardness . Other works support this finding, showing that soft prompt embeddings occupy re-gions in the embedding space that are distinct from those containing natural language (Bailey et al., 2023). A number of methods designed to optimize soft prompts for interpretability have found a trade-off between task performance and interpretability (Patel et al., 2025), (Deng et al., 2022). Closer to the idea of translating a soft prompt into natural language, Ramati et al. (2024) recently proposed InSPEcT, a training-free method of elicit-ing textual descriptions of soft prompts. InSPEcT works by utilizing the Patchscopes (Ghandehari-oun et al., 2024) framework to patch soft prompt activations into a target prompt designed to ver-balize descriptions of the task. While InSPEcT can successfully verbalize correct class labels for a given task, we found that verbalizations are of-ten unreliable, sensitive to the specific source and target layers used for patching, and often contain unnatural language. Their experiments were also quite limited and assessed verbalization on only a handful of datasets. To date, there is no method which can reliably, fluently, and robustly (without any performance-interpretability trade-off) translate soft prompts into natural language. We thus explore whether a more powerful translation model can help. 

3 Translating from Soft to Hard Prompts 

We explore a simple workflow (see Figure 1) for translating soft prompts to natural language whereby a dedicated translation model is trained with supervised learning on a dataset of ( soft prompt, hard prompt ) pairs. Here, each soft prompt was itself optimized for a specific task – e.g., sen-timent classification – on a fixed LLM (typically small and open-source, e.g., Llama-8B) using a dataset of ( input , output ) pairs. The trained trans-lation model, given some soft prompt trained on the same LLM, can produce a corresponding “hard prompt”, i.e., a natural language translation of the soft prompt. For a sentiment classification soft prompt, the hard prompt might be, “Examine the input sentence and classify it as positive or negative. A sentence is positive if...” 

Optionally, the generated hard prompt can then be fed to another LLM (typically larger and with a closed API, e.g., GPT-5.5). Given a high-quality verbalization and an arbitrary input example, the larger model possibly delivers higher task accu-racy compared to the small LLM on which the soft prompt itself was trained. 

4 Experiments 

We conduct experiments to investigate the follow-ing research questions: (1) Can a dedicated trans-lation model produce more accurate soft prompt translations as compared to just in-context learning methods (such as InSPEcT)? (2) What aspects of the translation model’s training set (size, composi-tion, etc.) are important? (3) Are the verbalizations simply plausible-sounding prompts, or are they ac-tually relevant to the task and useful for inference?

An example of ( soft prompt, hard prompt ) might be ( (0 .12 , −1.94 , . . . ), "Classify the news article as: Sports, Business, World, or Culture" ), where the array of num-bers is the real-valued vector representing a soft prompt. Each unique soft prompt in the transla-tor’s training set also needs to be trained on its own dataset of paired ( input, output ) sequences for some unique downstream task. For example, for a news classification task, the dataset might contain pairs: ("Oil and Economy Cloud...", "Business") , (Indians Beat Twins 7-1...", "Sports") , ("Democratic Senator Urges Energy Reform...", "World") , etc. To train a translation model, we thus need a dataset of datasets (DoD). Prior work on deci-phering soft prompts (e.g., (Ramati et al., 2024)) evaluated on just 5 datasets and is thus insuffi-cient. Instead, we construct two different DoDs: one synthetic dataset for classification tasks, and another based on the Super-NaturalInstructions dataset (Wang et al., 2022) for natural language tasks such as Text Summarization, Question Gen-eration, Machine Translation, etc. 

4.2 Datasets of Datasets (DoDs) Classification DoD : To examine soft prompts opti-mized for text classification tasks (like the kind used by (Ramati et al., 2024)), we generated a DoD containing 5500 datasets and 2.75 million sentences in total. Each dataset contains 5 class labels that are tightly semantically clustered. For example, one dataset comprises the labels music, films, books, art, software . To generate each label set, we randomly selected a keyword from the Brown Corpus (Francis and Kucera, 1979) as an “abstract concept” and used it to prime an LLM to generate a set of 5 distinguishable related labels. See Appendix A.2 for details. Within a dataset, each class is associated with 100 sentences (thus, 500 sentences in total per dataset). We generated sentences for each class using an LLM. For class and sentence genera-tion, we used mistralai/Mistral-Small-3.1-24B-Instruct-2503 as it is a stronger model than our chosen base model. An example of ( input ,

4.3 Training Details Soft Prompt Training : For each of the two DoDs, we first trained soft prompts: For the Classification DoD, we used an 80/20 train/validation split per dataset and trained a soft prompt consisting of 20 virtual tokens using a learning rate of 1e-4 for 20 epochs (patience of 5 epochs based on the valida-tion set loss), batch size of 32, and the AdamW optimizer. For the General DoD, we used a 90/10 split per dataset, learning rate of 1e-3, 20 epochs (patience of 3 epochs), and batch size of 8. The trained soft prompts for Classification DoD achieved 73.73% average validation task accuracy (i.e., correct classification rate), while soft prompts for General DoD achieved average validation task ROUGE-L of ~0.17. We note that, although the low ROUGE-L score suggests weak soft prompt performance, the General DoD tasks are often very challenging. Moreover, it is possible that, while the LLM is unable to reliably generate the correct response due to its modest size (8B parameters), the soft prompt itself might nonetheless encode the correct task that the LLM is supposed to be doing. In fact, we show evidence supporting this in Section 5.2 and Appendix A.9. More details on soft prompt training can be found in Appendix A.4. 

Translator Training : We train two trans-lator models in total (one for Classification DoD, and one for General DoD). For each, we used a 90/10 train/test split on the ( soft prompt , hard prompt ) pairs in each DoD. We used LoRA to fine-tune the base LLM (meta-llama/Llama-3.1-8B-Instruct ) and the following hyperparameters: learning rate of 1e-4, 5 epochs, batch size of 16, LoRA rank as 4, LoRA dropout as 0.1, with AdamW optimizer with weight decay of 0.1. More details are in Appendix A.5. For the Classification DoD, we define the tar-get hard prompt for each dataset as a string con-sisting of a comma separated list of the 5 class labels, e.g., "nurse, physician, surgeon, pharma-cist, radiologist" . For the General DoD, target hard prompts were already provided by the Super-NaturalInstructions dataset itself. 

4.4 Evaluating Soft-to-Hard Prompt Verbalization Quality 

We evaluate both the translator and the InSPEcT method on multiple datasets of datasets: Classifi-cation DoD, General DoD, as well as the set of 5 datasets used in (Ramati et al., 2024), namely: SST-2 (Socher et al., 2013), SST-5 (Socher et al., 2013), AG-News (Zhang et al., 2015), Subj (Pang and Lee, 2004), and TREC (Voorhees and Tice, 2000); for the remainder of this paper, they will be referred to as InSPEcT datasets. 

Metrics : For classification tasks (Classification DoD, and the 5 InSPEcT datasets), we compute the Recall of the ground-truth label set (this was called Class Rate in (Ramati et al., 2024)). We also compute the F1-Score (harmonic mean of Re-call and Precision rates) to account for “runaway generations”, as it penalizes the presence of irrele-vant tokens. For general tasks (General DoD), we use ROUGE-L and cosine similarity of embedded 4verbalized soft prompts (computed using the sen-tence transformer all-MiniLM-L6-v2 ) relative to ground-truth hard prompts. As a baseline, we also compare our translators against InSPEcT (see 5.1). We note that while InSPEcT is training-free, it has an important hy-perparameter: namely the pairs of layers used by the Patchscopes framework (Ghandeharioun et al., 2024) as part of InSPEcT. We found that InSPEcT is highly sensitive to this hyperparameter, and we thus optimized it on the training set of each DoD for all comparisons. See Appendix A.3 for details. 

4.5 Evaluating Relevance and Utility of Verbalizations 

Beyond measuring the similarity of the soft prompt’s verbalizations to ground-truth hard prompts (Section 4.4), we also evaluated the task performance of verbalizations when used as a prompt by a larger, downstream LLM on new in-puts. Specifically, we used the following method-ology: (1) Train a soft prompt using a small, open-source LLM for a certain task; (2) Use the transla-tor to verbalize the soft prompt into a hard prompt; (3) pass the verbalized hard prompt, along with an input example, to a large, closed-source LLM for inference on the same task (see Figure 1 for an illustration). If, using the verbalization as a prompt, the LLM performs at least as well as the original soft prompt, then that suggests the verbalizations are relevant to the task and useful for inference. It would also show that the verbalizations are portable hard prompts. We apply this procedure to tasks within the test-ing set of the General DoD: Using the associated translator model, we verbalize a predicted hard prompt and pass it to a closed-source LLM (GPT-4o-mini) for inference using the prompt template:

5.1.2 Data Augmentation + Simplification 

We also explored the effects of data augmentation on the ground-truth hard prompts. Subjectively, we found that the original hard prompts in the Super-NaturalInstructions dataset can be confusing and verbose (some instructions are 400+ words long). It is possible that using these as ground-truth for training the translator could hurt its performance, and thus we experimented with paraphrasing the original instructions to shorten and simplify them as a data augmentation measure. All paraphrased instructions are capped at 300 max tokens. We pro-vide results of translators trained using augmented datasets 1, 10, and 100 times the original size of the training set below. See Appendix A.8. Results are shown in Table 8 and suggest that, while augmentation of the DoD can improve trans-lation quality benefits, augmenting too much can hurt performance (possibly by diluting the effect of the original hard prompts). Though, subjectively we found the verbalizations were qualitatively more readable. For all remaining experiments in the pa-per, we thus used the translator trained on the 10x augmented General DoD.

5.2 Relevance and Utility of Verbalizations 

To assess whether verbalized soft prompts are useful for the task or merely plausible sounding prompts, we experiment with passing the verbaliza-tions to a larger LLM for inference (as described in Section 4.5) on a set of input examples. We com-pare this to (1) giving the large LLM the same inputs without the verbalization (“baseline”) as well as (2) giving the small LLM (SLM) the soft prompts themselves and with the input sentences. Results (Figure 3) show that the translated prompt, as used by the larger LLM, outperforms both the original soft prompt itself, as well as the baseline LLM without the prompt. This suggests the verbalization of a soft prompt is also a viable— and portable—hard prompt usable for inference. 

Comparison to Few-Shot Learning : Can trans-lating soft prompts trained on a smaller model into human-readable prompts outperform in-context few-shot learning, whereby the LLM implicitly infers a pattern from the given examples to make a prediction? We investigate this by applying few-shot learning on the same General DoD tasks using the same average task ROUGE-L metric. While for most of the tasks the few-shot learn-ing approach was more successful in terms of task accuracy (ROUGE-L), we did find a set of 10 tasks (out of 96) where the prompt that was discovered through soft prompt translation outperformed few-shot learning. 6 Discussion 

Over all our experiments, we found that the dedi-cated translation models consistently outperformed the training-free InSPEcT technique on the In-SPEcT datasets as well as the Classification and General DoDs in terms of quantitative verbalization quality. The translator also showed significant abil-ity to generalize out-of-distribution. Qualitatively, the translator’s verbalizations were mixed: some completely captured the goal of the task, whereas others missed the mark (often by a wide margin). The performance of the translator model, espe-cially its generalization capability, is surprising given the small training set size (539 samples). We speculate a possible explanation: the Rosetta Stone contained only a few thousand words in equiva-lent English translations, yet it was sufficient to establish a correspondence between ancient Greek and ancient Egyptian. Suppose that soft prompts constitute a language in their own right. It is pos-sible that LLMs already innately understand this language, and obviously they can understand and express natural language. The main difficulty in translating from soft to hard prompts is thus in find-ing a correspondence between these two languages, and perhaps a small dataset of ( soft prompt , hard prompt ) pairs is sufficient. This contrasts with, say, the LLM being fine-tuned to translate between two entirely new languages it was never trained on. Finally, the workflow we tested (far right side of Figure 1), whereby verbalized soft prompts can be passed to a large, more powerful LLM for infer-ence, showed promise. It has an important advan-tage over in-context few-shot learning that the soft prompt can be trained on a large dataset, allowing it to infer more nuanced patterns, whereas few-shot learning is generally limited to a small number of inputs due to token limits. 

7 Conclusion and Future Work 

Soft prompts are opaque and difficult to interpret. We show that by training a dedicated soft prompt translator model, it is possible to extract a hu-man readable, natural language translation of these soft prompts that is more accurate than the prior training-free InSPEcT approach. Verbalizations ob-tained from the translator are useful and relevant to the task at hand, which also potentially opens up a new workflow for obtaining portable prompts that can be applied onto closed source models. With a more powerful soft prompt translator trained on a larger dataset, it may be possible to train soft prompts on tasks with the specific goal of later translating them to learn new knowledge. It would be exciting if, after training a soft prompt for a complex task—like drug discovery (Liu et al., 82026)—insights into the mechanism of how the LLM makes its predictions (e.g., the molecular in-teractions) could be expressed in natural language. 

8 Limitations 

We did not explore in this work whether our soft prompt translator model can work with soft prompts trained on a different base model, though given that soft prompts are not normally trans-ferrable between models, it is safe to assume this is not the case. This means unless the soft prompt is already trained using the same base model as ours (Llama-3.1-8B-Instruct), a new translator model would need to be trained. While testing the soft prompt translation model out of distribution on real-world tasks, we noticed that while verbalizations were truthful and relevant to the task, it was often the case that they were also terse and lacked relevant details. We believe this is an issue with stylistic alignment—where the translator is erroneously choosing to omit relevant task details to produce more fluent verbalizations. See Appendix A.12 for further details. As is, soft prompt translation is a promising proof of concept. In order for it to become a practi-cal tool, however, a larger dataset is needed along with dedicated stylistic alignment (i.e.: preference optimization or Supervised-Fine Tuning on real world datasets) to ensure verbose, informative ver-balizations.

A.2 Synthetic dataset creation details 

For Classification-DoD generation, we utilized two separate vLLM pipelines for related keyword gen-eration and sentence generation. 

Keyword Generation : To choose keywords for a mini-dataset, we used a vLLM pipeline which sampled 3 random (nouns or adjectives) from the 10 Brown Corpus (Francis and Kucera, 1979), and primed an LLM with the sampled random key-words as “abstract inspiration” to generate dis-tinct words as classes which are related by con-cepts, industries, themes, etc. For each dataset, we generated 5 keywords as the dataset’s classes. We used mistralai/Mistral-Small-3.1-24B-Instruct-2503 as the LLM for keyword gener-ation. 

Sentence Generation : Using chosen key-words per mini-dataset, we generated 100 sentences per keyword (500 sentences per dataset), using mistralai/Mistral-Small-3.1-24B-Instruct-2503 . This dataset generation pipeline uses the vLLM library to efficiently batch requests together for higher generation throughput. Each mini-dataset was stored in a single SQLite3 database file, in a relational database manner on 3 tables, for fast and easy retrieval during the soft prompt training phase. For each mini-dataset, we store the generated sentences with their ground-truth class label, which was used to generate the sentences. Due to the constraint that the classes selected must be related to each other, we had in-stances where some mini-datasets contained classes which are very difficult to differentiate such as: 

revive, stimulate, inspire, encourage, motivate , which are generated from using the ab-stract word energize . Due to this, we observed many soft prompts with task accuracy below 50%.

A.9 Correlation between Interpretability and Task Accuracy 

While testing Classification DoD translator on the testing split of Classification DoD, we observed an interesting phenomenon: the accuracy of the soft prompts does not need to be high in order to get good verbalizations out of them. For example, most verbalizations of the soft prompts from the testing split of Classification DoD are commend-able in terms of Recall and F1-score, despite having low task performance (< 50%). This is contrary to the idea proposed in the InSPEcT paper, where they claim a correlation between quality of verbal-izations and the task accuracy of the soft prompts. Some verbalizations for soft prompts with low task accuracy can be found in table 10. We hypothesize that while the soft prompt ap-plied on the LLM may achieve poor performance, this might not just be because they encode irrel-evant task instructions; another valid possibility is that the soft prompt does encode relevant task instructions, but rather our small base model of only 8 billion parameters may be failing to execute them. This hypothesis is consistent with our finding in the General DoD: we showed that extracting the in-structions encoded within the soft prompt using the translator and passing these instructions to a larger, more capable LLM results in better performance— indicating that the soft prompts encode relevant task instructions but the smaller base model par-tially failed to execute them. Taking these soft prompts and verbalizing them with the translator, we can pass their encoded instructions to a larger, more intelligent LLM for inference on the same task. If the soft prompts do encode correct instruc-tions for a given task, we could then expect that a more intelligent LLM would be able to carry it out. Indeed, this was shown to be the case—in one in-stance (See: Fig. 4), while the original soft prompt had a task ROUGE-L of only 0.012, verbalizing the soft prompt and passing the instructions to an LLM achieves a task ROUGE-L of 0.8, surpassing even the performance of few-shot learning on the same LLM which achieved a task ROUGE-L of 0.4.

A.12 Stylistic Alignment 

A soft prompt is a high dimensional object hold-ing many details, some of which are trivial like expected formatting. In order to produce natural-language-like verbalizations, the translator must decide which details need to be omitted. In prac-tice, we found that there were many cases where verbalizations were too concise than ideal (for in-stance in figure 2). This is where style alignment can be applied to ensure that important details are not omitted. As a rudimentary method of encouraging a more verbose generation style, we experiment with pre-filling text. (i.e.: start autoregressive generation pre-conditioned on [soft tokens; prefill text]). Of-ten, after applying a prefill text, we see additional factual details in verbalizations. We show an exam-ple of one such case below in Fig 5. In this anecdotal example, the translator model omitted relevant task details in its original verbal-ization, which is only revealed once prefill is ap-plied. What this suggests is that, in such instances, the translator correctly comprehends the semantics of the soft prompt, but incorrectly omitted crucial details as a stylistic choice. This is a clear example of a stylistic misalignment which dedicated prefer-ence optimization could potentially address. To verify that this is not anecdotal, we also in-vestigated the effects of prefill conditioning more rigorously on 550 classification datasets from Clas-sification DoD.
