## 摘要
自动提示工程（APE）重写提示以提高下游任务性能，但现有的APE循环将优化器本身视为固定管道。我们将CodeAct（Wang et al., 2024a）的代码即行动范式移植到APE，并提出SPEAR（Sandboxed Prompt Engineer with Active Roll-back），一种具有四种工具的自由形式代理优化器——评估（evaluate）、Python、设置提示（set_prompt）、完成（finish）——它自主决定如何以及何时使用它们。其独特的工具是Python沙箱：优化器在当前评估DataFrame上编写并执行任意Python代码，执行代理自身编写的结构化错误分析（混淆矩阵、错误聚类、分组度量）。两个护栏将长程代理转变为单调改进的优化器：指标退化时自动回滚，以及可选的保护指标下限。我们在三个工业级LLM-as-judge套件（涵盖招聘摄入、对话记忆和查询精炼系统的13个评委任务）以及七个BBH任务和GSM8K上进行了评估。SPEAR在每个工业任务的主要指标上都胜出（工具选择上的κ 0.857 vs 0.359；过滤器相关性上的F1宏平均 0.815 vs 0.763；最难的提取维度上的κ 0.254 vs 0.218）。在BBH-7上，SPEAR平均准确率为0.938，而GEPA为0.628，TextGrad为0.484。消融实验表明，Python工具是复杂评委任务的最大单一杠杆（在5类工具选择评委上移除时Δ≈+0.79κ，在最难提取维度上移除时Δ≈+0.35κ）；其不可替代的贡献是类对混淆聚合，这是长上下文LLM无法从原始评估DataFrame中可靠提取的。

## Abstract
Automatic prompt engineering (APE) rewrites prompts to improve downstream task performance, but existing APE loops treat the optimizer itself as a fixed pipeline. We port the code-as-action paradigm of CodeAct (Wang et al., 2024a) to APE and propose SPEAR (Sandboxed Prompt Engineer with Active Roll-back), a free-form agentic optimizer with four tools -- evaluate, python, set_prompt, finish -- that decides autonomously how and when to use them. The distinctive tool is the Python sandbox: the optimizer writes and executes arbitrary Python on the current evaluation DataFrame, performing structural error analysis (confusion matrices, error clustering, per group metrics) the agent itself authors. Two guardrails turn the long-horizon agent into a monotone-improving optimizer: auto-rollback on metric regression, and an optional guard metric floor. We evaluate on three industrial LLM-as-judge suites (13 judge tasks across recruiter-intake, conversational-memory, and query-refinement systems) plus seven BBH tasks and GSM8K. SPEAR wins every industrial task on the primary metric ($κ$ 0.857 vs 0.359 on tool-selection; F1-macro 0.815 vs 0.763 on filter-relevance; $κ$ 0.254 vs 0.218 on the hardest extraction dimension). On BBH-7 SPEAR averages 0.938 accuracy vs GEPA 0.628 and TextGrad 0.484. Ablations show the Python tool is the largest single lever on complex judge tasks ($Δ\approx +0.79κ$ on the 5-class tool-selection judge, $Δ\approx +0.35κ$ on the hardest extraction dimension when removed); its irreplaceable contribution is class-pair confusion aggregation that a long-context LLM cannot extract reliably from the raw eval DataFrame.

## 1. 研究动机与核心问题

*   **背景**：自动提示工程（APE）通过重写提示提升下游任务性能，但现有方法（如TextGrad、GEPA）均将优化器设计为一个固定的、预先定义好的流程（fixed pipeline）。
*   **痛点**：固定流程的优化器无法根据评估结果动态、自主地执行结构化的错误分析（例如，发现特定类别对（class pair）的混淆、挖掘标签规则矛盾）。当错误具有结构化特征时，这种局限性限制了APE的性能上限。
*   **整体含义**：论文提出将“代码即行动”（code-as-action）范式引入APE，赋予优化器编写和执行代码的能力，使其从一个被动的流程转变为具备自主分析能力的智能体（agent），从而在复杂的、多类别的评判任务上实现突破性提升。

## 2. 方法论：SPEAR

SPEAR是一个自由形式的智能优化器，其核心思想是让优化器本身自主决定“如何”以及“何时”使用工具来分析错误并重写提示。

*   **核心工具集（Four Tools）**：
    *   `evaluate`：在训练/验证集上运行当前提示，返回评估指标和逐行预测结果。
    *   `python`：**标志性工具**。在AST受限的沙箱中执行任意Python代码。沙箱内提供一个包含当前评估DataFrame（含预测、真实标签、输入等）、`pandas`/`numpy`等库以及一个`llm()`辅助函数的只读环境。优化器自主编写如混淆矩阵、错误聚类、分组指标等分析代码。
    *   `set_prompt`：用新内容替换当前系统提示。
    *   `finish`：终止优化循环。
*   **智能体工作流**：优化器在一个`while`循环中自主选择上述工具之一执行，无固定顺序。典型的自主工作流为：`evaluate` → `python`（深入错误分析，如构建混淆矩阵）→ `set_prompt`（针对性重写）→ `evaluate` → ...
*   **安全保障（Guardrails）**：确保持续、稳定改进。
    *   **自动回滚（Auto-rollback）**：若`evaluate`后主要指标（如Cohen's κ）低于历史最佳值，自动将提示恢复为最佳提示。
    *   **保护指标下限（Guard-metric floor）**：可选配置，若某个次要指标（如精确率）低于预设阈值，同样触发回滚。
*   **算法流程**：优化器从种子提示P0开始，首先强制进行一次完整评估。之后循环选择工具。Python工具调用不消耗评估预算，可任意执行。`evaluate`全量运行消耗单位预算并更新最佳指标状态；样本评估不更新最佳状态，防止“筛选简单样本”作弊。

## 6. 主要结论与发现

*   **工业任务全面领先**：SPEAR在所有11个可比工业任务的主要指标上胜出，尤其在复杂多类别任务上优势巨大。例如，5分类的CMA tool-missing任务，κ从基线的最高0.69提升至**0.976**；最难的Hiring Assistant地点维度，κ从0.11/0.36提升至**0.76**。
*   **Python工具是关键杠杆**：消融实验证明，Python沙箱是最大的单一贡献因素。移除它会导致复杂任务性能急剧下降（CMA上κ下降0.79，地点维度下降0.35）。其独特价值在于能进行“类对混淆聚合”，这种结构化分析是向LLM直接灌输原始评估文本所无法替代的。
*   **公开基准的表现分离**：在BBH-7上的领先（平均准确率0.938 vs. 0.628）主要由**输出格式重写**驱动；在格式匹配的GSM8K上，所有方法均无明显提升。这表明SPEAR的架构优势在需要深层逻辑分析的复杂评判任务上才对提升性能起决定性作用。
*   **自主性与模型门槛**：自由形式的智能体循环比带有相同工具的固定流程效果更好，而智能体模型的质量（GPT-5.4 vs. GPT-4o）是系统正常工作的必要条件。
*   **案例研究发现**：代码执行使优化器能发现**标签规则矛盾**和进行**多类别混淆分析**，从而产生“规则变更”式的重写，而非仅仅优化推理结构。

## 7. 优点与亮点

*   **创新性集成**：首次成功将“代码即行动”范式应用于提示工程，将优化器从“被投喂错误信息者”转变为“主动分析错误者”。
*   **性能突破**：在极具挑战性的工业级多类别评判任务上取得了远超现有基线的性能。
*   **独特的分析能力**：通过Python沙箱实现的自主混淆矩阵、错误聚类等分析，解决了长上下文LLM无法从原始文本中可靠抽取结构化信息的痛点。
*   **可靠的优化机制**：自动回滚与保护指标下限机制，保证了优化过程单调改进，提升了系统在长程任务中的稳定性。
*   **详实的深度剖析**：通过深度的消融实验、案例研究和统一模型视角，清晰地揭示了各组件的贡献和系统的适用边界，实验分析非常扎实。

## 8. 不足与局限性

*   **复现性挑战**：核心优化器模型GPT-5.4是内部部署版本，外部人员无法精确复现。工业数据的专有性质也限制了结果的完整复现。
*   **数据与指标局限**：部分评估集（如CMA）样本量较小，可能放大方差；存在因数据集切分导致的开发-测试集指标正向偏差，虽非SPEAR独有，但影响结论的确定性。
*   **应用门槛**：高质量代码生成与分析能力严重依赖顶级的LLM作为智能体大脑，降级模型会导致性能崩溃。
*   **安全与泛化**：Python沙箱基于“信任的优化器”模型，非完全对抗性安全；优化后的提示长度大幅增加；优化的评判器会继承标注管线中的潜在偏见。
*   **优势特定性**：在仅需格式调整或无改进空间的高饱和任务上，SPEAR的架构优势不明显。
